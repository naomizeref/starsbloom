# Copy-trading review — 27 October 2026

The fixes below are local. No deployment, production database write, commit or push was performed.

## User experience

- Rebuilt the directory with searchable, responsive cards, visible allocation limits and duration, loading/empty states and retry feedback. Inactive profiles are excluded; their existing positions remain accessible.
- Removed invented performance charts, automatic “elite” badges and claims of verified live mirroring. The implemented backend stores term-based allocations; the interface describes that behavior.
- Allocation review shows available cash, cent amounts, target profit and total, with explicit early-exit terms. Failed requests preserve the amount and show an inline error. Insufficient balance offers a funding link instead of forcing navigation and discarding the draft.
- The native modal traps keyboard focus, focuses the amount field, restores focus on close and supports Escape. Closing, changing the amount and resubmitting are disabled during confirmation.
- A shared position panel on copy trading and portfolio shows saved terms, paused/matured states, payout feedback, cancellation confirmation and paid/cancelled history. Actions identify the position itself, so historical duplicates cannot cause the wrong allocation to be cancelled.

## Admin and persistence

- Corrected the `max_followers` field mapping. Capacity is enforced against unsettled positions, not the editable profile follower statistic. Zero/null capacity means no limit; a zero maximum allocation amount also means no maximum.
- Canonical null allocation limits now match the RPC instead of falling back to conflicting legacy aliases. The catalog-hook browser regression covers null/zero limits and capacity mapping.
- Admin forms have visible labels, numeric/term validation, image-read errors and pending controls. Errors appear beside save buttons on long mobile forms. Unsaved changes require confirmation before being discarded.
- Updating a profile sends only edited fields. A name/photo edit preserves existing limits, conflicting legacy aliases and chart history. Explicit limit edits synchronize the two aliases. New profiles no longer receive randomly generated chart data.
- The directory table has a keyboard-focusable scroll region and visible scrolling hint. Empty and read-error states are distinct.
- Allocation IDs use UUIDs. Position displays and notices use persisted terms rather than treating local projections as confirmed.

## Database changes and existing users

`copytrade_functions.sql` locks the account and then the trader before checking duplicates and capacity. New starts are rejected when that account already has an unsettled allocation with the same trader. These guards also apply to the legacy wrapper in the prepared bundle. Invalid ROI/duration terms are rejected before debit.

Cancellation still returns principal only. Matured positions must use the payout action, preventing an early-exit request from forfeiting maturity profit. Duplicate refund/payout protection remains enforced by the database.

These guards do not rewrite existing financial terms, balances, chart histories, catalog limits or open allocations. Existing duplicate allocations are retained and can be settled individually. The existing bundle's status-case normalization and additive metadata still apply as documented in the broader rollout notes.

The function updates are included in the existing **12-file** `dist/bloom-feature-upgrade.sql` bundle generated by `npm run db:features`. A frontend-only deployment leaves these database protections unapplied. Rehearse the bundle on a backed-up staging schema, verify hosted authentication/PostgREST and designated test-account create/cancel/claim actions, then coordinate the database and application release. The SQL lock order serializes starts, but parallel-session behavior still needs a hosted staging check.

The market-feed, stock-provider and live-configuration requirements in [the preflight review](bloom-preflight-review.md) remain separate whole-site release requirements.
